o1js 3 / Mesa
migration guide.

o1js 3.0 is a protocol migration, not a routine dependency bump. Use this checklist to make the verification-key, cache, transaction, and signer changes reviewable before anything reaches a live network.

The non-negotiable change

The official o1js 3.0 release notes say every verification key changes and caches must be regenerated. Record deployed hashes and owners before replacing an artifact.

Order of operations

A cautious migration sequence

  1. 01

    Freeze the starting point

    Use a dedicated branch. Record the current o1js and mina-signer versions, deployed verification-key hashes, cache paths, target network, and the people or systems that authorize upgrades.

  2. 02

    Generate a static inventory

    Run MesaGuard before changing dependencies. Keep its Markdown and JSON output with the migration work so removed APIs and committed artifacts remain visible during review.

    npx github:MartinOndejka/mesaguard scan . \
  --format markdown \
  --output mesaguard-report.md \
  --fail-on high
  3. 03

    Upgrade in isolation

    Move the relevant workspace to o1js 3, then compile and test from a clean install. Do not overwrite production caches or deployed-key records during this pass.

  4. 04

    Regenerate and map every key

    Compile each SmartContract and ZkProgram into an isolated cache. Map old and new verification-key hashes to their contracts, deployments, stored fixtures, APIs, and upgrade transactions. Treat every difference as expected by the protocol change but still requiring project review.

  5. 05

    Exercise transaction and signer paths

    Build representative transactions at boundary sizes, sign them in the intended era, serialize them, verify them, and submit only against an appropriate Mesa test environment. Include offline signers and wallet handoffs.

  6. 06

    Review the deployment plan

    Separate code migration from live key rotation. Confirm permissions, authorization, ordering, rollback assumptions, and downstream consumers before a production change. MesaGuard does not make this decision.

Concrete breakpoints

What to search for

KEYS & CACHES

Everything is regenerated

All verification keys change under Mesa. Locate committed `vk`, `pk`, SRS, step, wrap, and Lagrange artifacts as well as external object storage and deployed-key registries.

TRANSACTION COST

The old cost model is gone

Replace `setFeePerSnarkCost()` with `setFeePerAccountUpdate()`. Remove the floating-point `TransactionCost` constants and test against the 16-segment transaction limit.

JSON CONTRACT

VerificationKey.toJSON changed

The return value is now an object containing `data` and `hash`, not only a data string. Review types, fixtures, database fields, network payloads, and equality checks.

SIGNER ERA

Mesa is now the default

`mina-signer` v4 produces Mesa-format zkApp commands by default. Pin `era: 'berkeley'` only for a path that deliberately targets a legacy network, and test the full handoff.

PROTOCOL LIMITS

Copied constants can lie

State-field capacity rose from 8 to 32; action and event element limits rose from 100 to 1024. Find local copies, but verify behavior at meaningful boundaries rather than assuming more capacity is safe.

REMOVED GATES

Cairo types disappeared

`CairoClaim`, `CairoInstruction`, `CairoFlags`, and `CairoTransition` were removed. Any direct import needs redesign, not a renamed symbol.

Exit criteria

What “ready” should mean

Do not use a clean static scan as the exit criterion. Before approving a production migration, require evidence that:

  • every relevant contract and program compiles under the chosen o1js 3 version;
  • new verification keys and caches have named owners and reviewed destinations;
  • proof generation and verification run with representative inputs;
  • transaction construction, signing, serialization, verification, and submission are tested end to end;
  • stored JSON and external consumers accept the new verification-key shape;
  • deployment authorization and rollback assumptions are explicitly reviewed.
